# coop-split — исправленный комплект 1.1

Внутри готовый новый CoopInputRouter.exe для Windows x64 (.NET включён), ресурс coop_input, исходники и проверки. Прежний бинарник из присланного архива не использован. Предварительный отдельный client.lua заменён этой согласованной версией комплекта.

## Установка и первый запуск

1. Закройте старый роутер. Сохраните копию своей старой папки coop_input и EXE.
2. Скопируйте папку coop_input из этого архива в resources вашего ЛОКАЛЬНОГО FXServer, заменив старый ресурс. Не запускайте обе версии ресурса одновременно.
3. В server.cfg должны быть строки:

       set coop_input_port 30126
       ensure coop_input

   30126 — отдельный UDP-порт роутера. Не назначайте его одновременно игровым портом FXServer. При изменении порта исправьте его и в CMD. Приёмник слушает только 127.0.0.1; FXServer и роутер должны работать на одном ПК.
4. Перезапустите ресурс: restart coop_input в консоли FXServer. Подключите оба FiveM. В той же консоли выполните coopstatus; назначьте второе окно командой setp2 ID_ВТОРОГО_ИГРОКА. Это серверный ID, не номер окна Windows. Автовыбор: setp2 auto; отключить ввод: setp2 0.
5. Подключите DS4 по USB, закройте x360ce и старые экземпляры роутера. Не используйте несколько эмуляторов/отправителей одновременно. Запустите НОВЫЙ start-ds4-router.cmd рядом с НОВЫМ EXE.
6. Отпустите все кнопки, стики и курки на 200 мс. В HUD второго окна должен появиться OK, частота примерно 60 pkt/s. Ввод до общей нейтрали намеренно блокируется.
7. Используйте оконный/безрамочный режим FiveM. Если доступен параметр Pause On Focus Loss, выключите его для фонового окна. Сначала проверьте ходьбу и камеру, затем машину.

Роутер уже преобразует DirectInput в нормализованный формат XInput. В клиенте оставьте профиль xinput, даже если DS4 читается с --directinput. Команда: coop_profile xinput. Другие профили нужны только для диагностики альтернативного отправителя.

## Камера

По умолчанию используется только нативный ввод LOOK. Если данные правильные, но во втором фоновом окне камера не реагирует, выполните в F8 ВТОРОГО клиента:

    coop_camera manual

Вернуть штатную камеру:

    coop_camera native

В manual нативные оси камеры НЕ подаются одновременно с ручным изменением углов. Режим предназначен прежде всего для обычной камеры от третьего лица; вид от первого лица и прицел с оптикой требуют проверки в игре. Подтверждённый режим можно сохранить в поле camera_mode в начале client.lua.

Камера вверх/вниз наоборот: coop_invert. Однократно поставить за спину: coop_resetcam. Отключить до отпускания всех органов управления: coop_calibrate. Показать/убрать HUD: coop_debug.

## Управление

Пешком: левый стик — ходьба; правый — камера; крестик — бег; квадрат — прыжок; треугольник — сесть в транспорт; круг — перезарядка / удар без оружия; L1 — колесо оружия; R1 — укрытие; L2 — прицел; R2 — огонь; L3 — скрытность; Share — сменить вид камеры. Крестовина влево/вправо — быстрая смена оружия; вверх — телефон; вниз — информация HUD. Внутри колеса правый стик выбирает сектор.

Обычная дорожная машина: левый стик — руль; R2 — газ; L2 — тормоз и задний ход штатными средствами GTA; крестик — ручник; треугольник — выйти; L3 — сигнал; R3 — посмотреть назад; вправо — фары; влево — радио. L1+R1 — огонь из машины. R1 больше не включает ручник, а газ не стреляет автоматически при удержании L1. У пассажира газ и руль не подаются.

Это не полная раскладка всех режимов GTA: меню/телефон, самолёты, вертолёты, лодки и специальные машины отдельно не реализованы и не проверены. Options не переназначен. Другие ресурсы сервера могут блокировать управление или менять камеру.

## Если камера всё равно уходит или нет газа

Закройте обычный роутер и запустите diagnose-ds4.cmd. В окне появятся:

- Реальный диапазон каждой оси, прочитанный у драйвера.
- [DS4 raw] — X Y Z Rx Ry Rz до преобразования.
- [DS4 packet] — JSON после нормализации и мёртвых зон, который получает сервер.

При отпущенном контроллере в JSON lx/ly/rx/ry/lt/rt должны быть 0, buttons — 0. В начале нажимать курки для «разблокировки» НЕ нужно.

Последовательно, по одному: левый стик, правый стик, L2, R2. Для стандартного USB DS4 принята карта:

    LX=X  LY=Y  RX=Z  RY=RotationZ  LT=RotationX  RT=RotationY

Если ваш драйвер назначил оси иначе, их можно задать явно. Например, при ДРУГОЙ подтверждённой карте меняется список имён в параметре:

    CoopInputRouter.exe --directinput --diagnostics --axes X,Y,Z,RotationZ,RotationX,RotationY --port 30126 --hz 60

Порядок списка строго LX,LY,RX,RY,LT,RT. Допускаются шесть разных имён из X,Y,Z,RotationX,RotationY,RotationZ. Не угадывайте карту: сначала проверьте RAW. Поддерживаются отдельные курки с отпусканием у минимума и нажатием у максимума; объединённые или перевёрнутые курки требуют отдельной настройки кода по фактическим значениям.

Если JSON в покое нулевой, а камера движется, причина уже вне этой преобразованной оси: проверьте другие ресурсы камеры и физический ввод игры. Если первое окно тоже реагирует на DS4, DirectInput NonExclusive не изолирует устройство от игр; маршрутизация не скрывает контроллер Windows. HidHide/эмуляторы и их исключения нужно настраивать отдельно так, чтобы роутер видел DS4, а игры — нет. Не включайте/отключайте скрытие вслепую.

Если pkt/s = 0 или STALE: проверьте coopstatus, запуск EXE, USB, назначение P2, одинаковый порт и отсутствие второго роутера. Если pkt/s есть, но статус NOT ARMED — проверьте JSON в покое. Если JSON правильный и управление работает только в активном окне, проверьте режим камеры, паузу, фокус NUI и ресурсы, отключающие controls.

При проблеме пришлите вывод diagnose-ds4.cmd в покое и при каждом отдельном стике/курке, а также coopstatus и HUD второго клиента.

## Что исправлено в исходниках

1. DirectInputSource.cs больше не считает, что установка signed Range непременно удалась. После попытки он читает действительный диапазон КАЖДОЙ оси и преобразует его в -32768..32767. У неподдерживаемых диапазонов и значений есть явная диагностика; ошибки больше не замалчиваются. Добавлены --axes и --diagnostics.
2. client.lua не смешивает два способа движения камеры. Сглаживание учитывает время кадра, нейтраль сразу останавливает ввод. Небольшая дополнительная зона 0.04: основная мёртвая зона уже есть в роутере.
3. Убраны отдельные вечные блокировки L2/R2. Включение выполняется после общей нейтрали, при ошибке или разрыве связи всё состояние сбрасывается. Короткие нажатия между кадрами сохраняются на следующий кадр.
4. Исправлены конфликты ручника/стрельбы/газа, лишняя ось VEH_MOVE_UD и одновременная прямая смена оружия при выборе через колесо.
5. server.js принимает только полные нормализованные пакеты; сырые огромные значения больше не превращаются в зажатую ось через clamp. Используются JS API onNet и GetNumPlayerIndices/GetPlayerFromIndex. Приём остаётся на loopback.

## Проверки и сборка

Проверено в Linux:

- 55 проверок C# --selftest: диапазоны signed/unsigned/8-bit, кнопки, курки, валидация карты, JSON при разных локалях, реальный локальный UDP round-trip, потеря контроллера.
- 22 проверки client_harness.lua с имитацией FiveM: роли, нейтраль, отпускание камеры, оба взаимоисключающих режима, обрыв связи, неверные пакеты, газ/тормоз/руль, пассажир, короткие кнопки.
- 16 проверок server_harness.js: разбор пакетов, выбор P2, назначение слота, выключение, чужие источники, остановка ресурса. Cfx API и сокет здесь имитируются.
- node --check coop_input/server.js.
- Публикация self-contained single-file win-x64 EXE из исправленных исходников.

Запуск всех проверок: ./run_tests.sh (bash, .NET 8 SDK, Node.js и Lua 5.3+; здесь Lua исполнялся через fengari). На Windows готовый EXE проверяет преобразования командой CoopInputRouter.exe --selftest. Для пересборки используйте build-win-x64.cmd с .NET 8 SDK.

Физический DS4, DirectInput Windows, настоящий FXServer, два окна FiveM, NUI и фоновый игровой ввод в этой среде не запускались. Тесты на подставном API не доказывают работу движка. Код исправляет подтверждённые ошибки; абсолютное отсутствие багов без проверки на вашем ПК не обещается.
